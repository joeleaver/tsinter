# Real-application trial, round 3 (main @ 0beea529)

Not corpus programs. Round 2's nine app runs (see `../real-apps-round2/README.md`) repeated on the `wasm` and
`wasm-native` lanes against Node v24.18.1, on main @ `0beea529`. Since round 2, main has added undefined
handling (S119, S122 fatal fences), TypeScript module forms (cycles, builtin default imports, JSON imports,
re-exports; S124, S126, S127), the GH #107 internal-error fixes, width-copy identity (GH #109, S125), the
exports/hoisting fixes (GH #110, #111, #113), and lean tests without C/LLVM. **The stdlib-members unit (2B) is
not in this run**: it had not landed on main, so its `stdlib:js` blockers below are still open here.
Measurement only: the compiler is unchanged. `survey/` (the refusal survey over 302 npm packages and 106 repos)
is a separate study; this trial uses its family names.

## Headline

**0 of 9 apps run unmodified and match Node, on either lane** (round 2: 0). 3 of 9 build unmodified
(papaparse, polka, expr-eval; round 2: 2) and all 3 then stop at module init with a named runtime refusal
(exit 1). The other 6 refuse at build time with named diagnostics. With patches, chess.js matches Node on
both lanes for every workload except `pgn`, which now stops loudly instead of diverging silently.
**No silent divergence was found** (no app or workload built, exited as Node did, and printed something
different), and round 2's five silent repros are now all either fixed or loud.

## Layout

- `harness/`: everything needed to re-run this, with no paths into a session scratchpad. `common.py` holds the
  paths: the repo comes from the file's own location, and app copies and results go to `$RA_WORK` (default
  `~/.cache/tsinter-dl/work/real-apps-round3`). No third-party code is in the repo.
  - `verify-downloads.py` checks every tarball in `~/.cache/tsinter-dl/apps/` against the npm registry
    (`dist.shasum` + `dist.integrity`), against the sha256 in `SOURCE.txt`, and file by file against the
    extracted tree. All passed. The two GitHub source tarballs (marked, smol-toml) had no recorded hash. They
    matched a fresh codeload download byte for byte, and their sha256s are now recorded in `SOURCE.txt`.
  - `setup-apps.py` builds `$WORK/apps/<app>` from the downloads plus `drivers/`. The only edits to
    third-party files keep Node's behavior the same: import specifiers Node's type stripping can resolve
    (`./x.js` to `./x.ts`, and chess.js's `./pgn` to `./pgn.js`), and marked's CLI pointed at
    `src/marked.ts` instead of the built bundle. Round 2's toml/papa/polka/expr/marked-lib drivers and work
    files were lost with its scratchpad. They are rewritten here (`drivers/*-main.*`), so those rows'
    workloads are similar to round 2's but not identical. chess `bench.pgn` is generated by
    `drivers/chess-gen-bench-pgn.ts`: 200 seeded games produced under Node from the unpatched source.
  - `mkspecs.py` writes the case lists. `run-apps.sh [spec…]` runs Node, then wn, then wasm, one at a time,
    each in a 16 GB memory cap, then `cmp.py`. `lane.py` is round 2's runner: the wasm lane runs inside
    vitest through a copy of `tests/harness/wasm-differential.test.ts` with an argv hook plus
    `realprobe-tail.ts.txt`. That copy is written to `tests/harness/zz-realprobe.test.ts` only for the
    duration of a run.
  - `chess-variant.py <skip-cats> <dst>` is round 2's script: it rebuilds chess.js 1.4.0 with the round-1
    patches minus the named categories, plus one new category, `histsplit`.
    `drivers/chess-nobigint-head.ts` is a reconstruction of the lost 32-bit Zobrist head. `ablate.sh` runs
    the per-category ablation. `semver-patch.py` builds round 2's hoisted-require semver variant.
  - `blockers.py` runs `sites.mjs` (`analyze()` hooked to lower as the WasmGC lanes do, exactly like
    `survey/worker.mjs`) and classifies each root site with `survey/families.py`. Its output is
    `blockers-census.txt`.
  - `check-repros.py` sorts single-file repros into MATCH / SILENT / LOUD / REFUSED on both lanes. `perf.py`
    and its raw output `perf-raw.txt` hold the performance runs.
- `blockers/01-overload-return-width-copy-S125.ts`: the one new blocker since round 2 that broke a build
  round 2 had working (loud, see below).
- `silent/` is not created: this round found no silent divergence to put there.

### chess.js: which patch categories are still needed (each removed alone, rebuilt, re-run on wasm-native; wasm build checked)

The full patched variant (`chess-v`) and the minimal one (`chess-min`, every category below marked "still
needed") match Node on 8 of 9 cases on both lanes. The one exception is `pgn`, which exits 1 (see
"Silent divergences").

Still needed (the build refuses without the category):

- `bigint`: 12 root sites.
- `formulti`: 9.
- `sparse`: 4. The first is now `new Array(count)` (SC2020).
- `privbracket`: 3.
- `tsgocrash`: 1, the SC0004 typescript-go panic.
- `throwbang`: 1.
- `compound`: 10.
- `inop`: 4.
- `untypedarr`: 13 root sites, 17 errors.
- `looseeq`: 1.
- `pgnheaders`: 2. The first is now `for-in over 'any'` (SC1052).
- `pgn_proto`: builds without it, but all 8 non-pgn cases exit 1 at module init: `peg$subclass(peg$SyntaxError, Error)` hits "builtin 'Error' used as a value", now a fatal fence.
- **`histsplit` (new, 2 sites)**: `history()` fills one `(Move | string)[]` and its overloads hand it out as `Move[]` or `string[]`. Since GH #109 that is an S125 width copy and refuses by name (`blockers/01-…S125.ts`). Round 2 built this. The new patch keeps one exactly-typed array per overload, a change that leaves Node's output the same.

No longer needed:

- `pgn_in` (new since round 2: `k in peg$startRuleFunctions` builds).
- `typeofargs`, `defparam`, `recundef`, `popguard` (as in round 2).

Net: 13 categories (round 2: 12), with one gone and one new.

Workloads on `chess-min`, all MATCH on both lanes unless noted:

- the 9 cases, minus `pgn` (loud);
- 4 text-fuzz runs (`fuzztext k 1500`);
- 4 game-fuzz runs (`fuzz k 60`);
- 6 deep perft/fuzz runs (perft 5, kiwipete 4, positions 3–5, `fuzz 12345 250`), checked on wasm-native only.

## Performance (chess.js, CPU user+sys seconds, median of 3, pinned to one core with `taskset`, the three subjects interleaved per repetition; raw: harness/perf-raw.txt)

| workload | Node, original src (bigint keys) | Node, patched src (same as compiled) | wasm-native | wn / Node-patched |
|---|---|---|---|---|
| startup (`bogus`, exit 2) | 0.23 | 0.22 | 0.00 | — |
| play 1 300 | 0.45 | 0.37 | 0.15 | 0.42× (startup-dominated) |
| fuzztext 1 1500 | 0.52 | 0.54 | 0.30 | 0.55× |
| perft 5 (4.87M nodes) | 4.97 | 3.39 | 11.29 | **3.3×** |
| perft 4 kiwipete | 4.14 | 3.04 | 9.52 | **3.1×** |
| fuzz 1 60 (verbose moves, SAN, undo) | 5.39 | 3.71 | 11.08 | **3.0×** |

All 18 interleaved triples printed identical stdout. Round 2's runs were unpinned on a loaded box, so absolute
times are not comparable. In ratios, perft is unchanged (3.1× then, 3.3× now, within noise) and game-fuzz
moved from 2.4× to 3.0×. That difference is near the noise of round 2's numbers, but the minimal variant now
carries `histsplit`, which makes `history({verbose})` build a second array, so a small real shift is possible.
On the wasm lane (in-process V8, wall time only), the 100-game fuzz cases ran 4–8.5× slower than Node's CPU time
(round 2: 10–15×; not like-for-like, different box load).
